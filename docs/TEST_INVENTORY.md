### `api/15-password-management.spec.ts` (25 declared blocks)

**POST /auth/change-password (authenticated)**
- rejects an unauthenticated request with 401
- rejects a missing/short/whitespace-only/over-long/non-string newPassword with 400 (never 500)
- requires the current password when the account has one, and rejects a wrong one — password unchanged
- a non-string currentPassword is a 400, not a 500 (Finding 16, fixed in 0563993)
- changes the password: old one stops working, new one works; the response carries a fresh working session token
- every session issued BEFORE the change is revoked, the fresh one survives (Finding 15, fixed in 0563993)
- one user's change never affects another user's password or session
- a change followed by a second change works with the fresh token (version keeps incrementing)

**session tokens (tokenVersion revocation)**
- a legacy token WITHOUT a tokenVersion claim still works for an account that never changed its password (no forced logout on deploy)
- a legacy token stops working once the password has been changed
- a token with a future/other tokenVersion (number or string), or for a user that does not exist, is rejected with 401

**register / login validation and hasPassword (Findings 19, 21)**
- register and login both return hasPassword: true (Finding 21, fixed in 0563993)
- register rejects whitespace-only and over-72-character passwords, accepts exactly 72 (Finding 19)
- register / login reject non-string email or password with 400 (never 500)

**POST /auth/forgot-password (public)**
- answers identically (status AND body) for an existing and an unknown email — no enumeration by response
- rejects missing / empty / non-string emails with 400
- is case- and whitespace-insensitive on the email, and issues a 64-hex token
- a newer request invalidates the previous, unused token
- the emailed link ignores an attacker-supplied Origin or Referer (Finding 14, fixed in 0563993)

**POST /auth/reset-password (public, token from email)**
- resets the password: new works, old fails, and the token is single-use
- a wrong token, a wrong email, and an unknown email all fail with the same 400 body (no enumeration)
- validation failures (missing, short, whitespace-only, over-72, non-string) are 400 and do NOT consume the token
- tolerates a padded token and a mixed-case email
- concurrent use of one token succeeds exactly once (no double-spend race)
- a reset revokes every existing session, including one held by an attacker (Finding 15, fixed in 0563993)
